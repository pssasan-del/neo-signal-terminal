# LION BRO – Final Consolidated R2
Release ID: `LION-BRO-2026-09-16-R2`

This package consolidates the current bright LION BRO UI, holdings/option-chain work,
Explosion Detector and the following R2 corrections.

## R2 corrections

1. **Truthful market status**
   - Green `MARKET LIVE` only when Kotak is authenticated, market stream is running,
     websocket is connected and the feed is fresh.
   - Amber `MARKET WAIT` when authenticated but live ticks are not fresh.
   - Red `BACKEND UPDATE` when the app is connected to an older backend build.

2. **Signals**
   - Normal strategy signals continue to come from the existing signal engine.
   - Signals screen refreshes every 5 seconds instead of loading only once.
   - Normal signal generation remains independent of Explosion Detector.

3. **Explosion Detector**
   - Separate ON/OFF control and alert-only engine remains intact.
   - Telegram alert is sent for TRIGGERED / EXPLOSION / RE-EXPLOSION states.

4. **Option chain**
   - App requests ATM ±3 strikes (7 strikes total where the broker supplies both sides).
   - Telegram command `option chain` returns Spot, nearest expiry, CE premium/OI,
     Strike, PE OI/premium for NIFTY, BANKNIFTY and SENSEX.
   - `option chain nifty`, `option chain banknifty`, `option chain sensex` are supported.
   - `/optionchain`, `/optionchain nifty`, etc. are also supported.

5. **Telegram alerts**
   - Every lifecycle signal generated by the normal engine is sent to Telegram.
   - Signal lifecycle state changes are sent to Telegram.
   - Explosion Detector trigger alerts are sent to Telegram.
   - `/signals` returns recent signals; `/status` returns Kotak/market status.
   - Only the configured TELEGRAM_CHAT_ID can issue commands.

6. **TOTP / session behaviour**
   - On app launch, `/auth/status` is checked first. If the backend Kotak session is
     already authenticated, the app opens directly without asking for TOTP again.
   - Backend sends a low-frequency session keepalive while it is running.
   - This does NOT bypass Kotak security. If Kotak expires/invalidates the trade session,
     or the backend is restarted and the SDK session is lost, a fresh TOTP is legitimately required.

7. **Holdings**
   - Existing enriched holdings logic is preserved: broker `instrumentToken` live quote first,
     then broker `closingPrice` as explicit PREV_CLOSE fallback; no fake zero / -100% P&L.

## Required backend .env additions

Keep all existing Kotak and APP_API_TOKEN values. Add:

```env
TELEGRAM_ENABLED=true
TELEGRAM_BOT_TOKEN=YOUR_BOT_TOKEN
TELEGRAM_CHAT_ID=YOUR_CHAT_OR_GROUP_ID
KOTAK_SESSION_KEEPALIVE_SEC=240
```

Never put the real bot token in GitHub.
